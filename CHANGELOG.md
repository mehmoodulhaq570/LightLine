# Changelog

This is LightLine's development history. Dates are the GitHub commit dates in Asia/Karachi (UTC+05:00). The project has no tagged release yet, so these dates do not represent releases. Planned architecture is documented separately in [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 2026-09-20

- Added go-to-definition and document formatting to the LSP client for both Rust and Python. **F12** (or the **Go to Definition** command) jumps the cursor to the symbol's definition, opening the target file in a new tab when it lives elsewhere; **Shift+Alt+F** (or the **Format Document** command) applies the language server's edits back-to-front so the document stays in sync with the server. Both route through the same id-keyed request tracking already used for hover, and the shared `Pending` request map now carries hovers, definitions, and formats.
- Opening a file that is neither valid UTF-8 text nor a decodable image now falls back to a read-only hex-dump preview (offset, hex columns, and an ASCII gutter, truncated past 64 KiB) instead of failing with a "Only UTF-8 files are supported" error. The generated preview is seeded as a clean, non-dirty document and blocked at the shared edit and save choke points, so it can never be accidentally written back over the real bytes.

- Added a hand-rolled, dark-themed modal dialog (Yes/No/Cancel and OK, matching the workbench palette) and opted the process into native dark mode for the remaining common dialogs (Open/Save file pickers), using the same undocumented `uxtheme.dll` preferred-app-mode entry points several other dark-themed Windows apps rely on. The interactive terminal now loads your normal PowerShell profile by default (custom prompt, aliases, PSReadLine settings), matching how a real terminal should behave; the dedicated Output session used for `cargo test` and Run Python still skips profile scripts, since that session is meant to be fast and deterministic rather than interactive. Added a **Restart Terminal** command and a **Restart Terminal (No Profile)** command (Ctrl+P, type `>`) to recycle a stuck or misconfigured shell without closing and reopening the panel. ([41194ae](https://github.com/mehmoodulhaq570/LightLine/commit/41194aec25bbd4f65fd2d0e08b3e3ad2f271f9a7))
- Replaced the legacy folder picker with the same modern folder-browser dialog File Explorer and most current editors use (`IFileOpenDialog`), so it follows the OS's light/dark setting automatically instead of showing mismatched light-mode chrome against the dark workbench. Split the bottom panel into two independent sessions with their own tabs: **Terminal** is the persistent interactive shell (type freely, paste with Ctrl+V or Ctrl+Shift+V, scroll back, Ctrl+C interrupts the foreground program); **Output** is a read-only view of `cargo test` and Run Python results — it never takes keyboard focus or shows a cursor, matching how other editors separate task output from an interactive shell. Running something no longer types into whatever shell you happened to have open. Clicking the Terminal tab starts a shell automatically if none is running yet. Fixed the PowerShell syntax error ("Unexpected token '-u'") that broke every Run Python invocation, caused by a missing call operator (`&`) before a quoted interpreter path. The sidebar and the terminal panel can now be resized by dragging their edges; the sidebar's width is remembered across hiding and showing it again, and the terminal panel's height — previously a fixed constant duplicated in six places across the UI code — is now a single resizable value. Fixed several rough edges found while dogfooding the new terminal and file browser: canonicalized paths no longer leak their `\\?\` extended-length prefix into the terminal prompt, the recent-workspaces list, or the Git review panel; long file paths in the Changes panel now truncate with an ellipsis instead of being hard-clipped mid-character; the Quick Open list no longer overlaps its own "Type > for commands" hint when it's full; the three Start-screen buttons (Open file / Open folder / New file) now share equal visual weight instead of only the first one looking clickable; the Explorer's previously nonfunctional icon button now collapses all expanded folders; and the editor's caret no longer renders on top of the terminal's own cursor while the terminal has focus. ([e2df00d](https://github.com/mehmoodulhaq570/LightLine/commit/e2df00dcfa04cd6636358c5c33eee8a4cde9f03a))
- Added Python syntax highlighting via `tree-sitter-python`, sharing the same incremental background worker already used for Rust; oversized Python files fall back to plain text instead of the Rust path's lexical fallback, since Python's tokenization does not lend itself to the same lightweight scanner. ([1c49132](https://github.com/mehmoodulhaq570/LightLine/commit/1c491326bd51f2735a25d301ed13aebce8179e7c))

## 2026-09-19

- Added terminal input encoding (key and paste sequences, including bracketed paste) and dynamic PowerShell 7 resolution with a Windows PowerShell fallback, launched interactively with a no-profile restart path — the ConPTY-backed foundation the full terminal panel above was later built on. ([ee20bd5](https://github.com/mehmoodulhaq570/LightLine/commit/ee20bd536352e7e0fcb47285f87df4dea153a508))
- Replaced the tab-bar Run Python text label with a VS Code-style green play button (hovering it shows the Ctrl+Shift+R hint in the status bar, and its clickable area was widened so the hint is never clipped), and made LightLine auto-detect the Python interpreter — a `.venv` in the project or its parents first, otherwise the first `python.exe` on PATH — for both Run Python File and Pyright import resolution, so no manual selection is needed unless you want to override it. The Run & Debug rail now runs the active Python file when a `.py` file is focused instead of reporting a Cargo.toml error, and raw language-server spawn failures (for example Pyright missing from PATH) show an actionable install hint in the status bar instead. Covered by detection and message unit tests. ([242b297](https://github.com/mehmoodulhaq570/LightLine/commit/242b29739c8353fd747e2db7cc0dbd402eb8f033))
- Added a Run Python File command (Ctrl+Shift+R, a tab-bar button, and a Ctrl+P command) that runs the active `.py` file with the selected interpreter or virtual environment in the file's detected project folder. Output streamed to an input-capable terminal panel: stdout and stderr appeared as produced, typed input was sent to the process's stdin on Enter, Stop and Ctrl+C ended the whole process tree, and the panel showed the exit status (this panel was later replaced by the dedicated Terminal/Output split above). Saves dirty files before running, or prompts when a path is required first. All process spawning, streaming, and cancellation run on background threads and are cleaned up on stop or window close. Added workflow tests covering streamed output, a Python traceback and nonzero exit, interactive `input()`, cooperative cancellation, and Python project-root detection. ([1b09d6e](https://github.com/mehmoodulhaq570/LightLine/commit/1b09d6e36d3e19344dd5d2721ad7ecffeac39549))

A global install still takes precedence, and if Node.js itself is missing the status bar explains that instead of a raw process error. Added first-class Python language support through the shared LSP client: lazy Pyright startup for `.py` files, diagnostics and hover, per-session interpreter or virtual-environment selection for import resolution, and independent server failure handling that keeps editing responsive. ## Status after the 2026-09-20 commits

LightLine has a native Windows editor with Rust and Python syntax coloring, rust-analyzer and Pyright language support, multiple tabs, split panes, project search, Quick Open, Git review, and an integrated terminal with a persistent interactive shell (Terminal) separated from build/run output (Output). A debugger, extension marketplace, and AI assistant remain future or conditional work.
