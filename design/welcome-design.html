Welcome page: proposal

Today's Welcome page beside a flatter one that matches the rest of v0.11.0's VS Code-style layout. Both are at the same 125% scale. The proposal keeps every working action, drops the decoration and the duplicates, and fixes three things that don't work. Point at rows to see their hover state; the toolbar switches between states.

Hover the speed pill for what it measures.

What changes, and why

  1. Flat, like the rest of v0.11.0. The page sits on the editor's own background, with section labels in the side panels' style (11 px capitals) instead of four bordered cards and a gradient hero. The rail is the editor's rail (48 px, a 2 px bar on the open view, no tile), so going from Welcome to a file no longer changes the chrome.
  2. No decoration. The editor illustration, "CODE BUILD DEBUG CREATE", "A brighter development tomorrow" and "Build Faster. Think Smarter." go. They took half the page and did nothing. "AI-powered" goes too: AI is opt-in, and speed is what LightLine is about.
  3. Each action once. Today Open Folder appears three times, New File and Search twice, and the status bar repeats the shortcuts a fourth time. Now Start has New File, Open File and Open Folder, and Get started has the six things worth learning first, each with its key.
  4. More of Recent. Eight folders instead of three, one 28 px row each (name, then its folder dimmed, then its age), instead of 50 px rows with a dead "View all". Point at a row for × to remove it from the list.
  5. Speed you can see. A small "Started in 84 ms" pill: the time from launch to this page being drawn, measured on every start. It's the one claim LightLine makes about itself, shown where it can be checked.
  6. Narrow windows. Below about 1,150 px the halves stack, Get started drops its descriptions, and Recent shows five; nothing is cut off. Today Getting Started disappears instead.

Fixed along the way

  • Command Palette is labelled Ctrl+P today but opens Go to File. It becomes Ctrl+Shift+P and opens with >, and Go to File gets its own row.
  • View all → next to Recent Projects isn't clickable. It's gone; the list is longer instead, and File → Open Recent is still there.
  • Run your first build runs the active file, but the Welcome page has none, so it can only fail. It's replaced by rows that work from here.
  • The status bar's Ctrl+O file • Ctrl+N new • Ctrl+Shift+O folder repeated the page. It keeps Ready and the branch.

Kept: the title bar and menus, every rail button, Settings at the bottom of the rail, all six Quick Actions (now in Start and Get started), the Recent click to open, the GitHub links (now under Learn, as in the Help menu), and Ctrl+Shift+H.

To decide
