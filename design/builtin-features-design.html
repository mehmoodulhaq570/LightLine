Built-in Daily Features

Five features that VS Code users get from extensions on day one, built into LightLine instead. Zed's registry has nothing for them, and Zed extensions can't draw on the screen, so no extension store could provide them. Each one is off until it's needed, reuses data LightLine already has, and has its own setting. Use Today and Proposed on each to compare.

1. Errors at the end of the line like Error Lens

The language server's message is written after the line in the error's colour, so you can read it without hovering or opening Problems. The line the caret is on shows its message brighter. A long message is cut off at the window's edge with …; hovering still shows the whole thing. When a line has more than one problem, the worst is shown, followed by +1.

Details

  • Setting inlineDiagnostics: "off", "errors" or "errorsAndWarnings" (proposed default). Hints and info stay as squiggles only.
  • Placement: 28 px after the last character. If the line is wider than the window, nothing is drawn: no message on a line that fills the screen.
  • Word wrap: after the last row of the wrapped line.
  • Updates: when the language server sends new diagnostics, only the rows whose message changed are redrawn.

Speed

  • At most one short ExtTextOut per visible row that has a problem, cut to the space left. Rows without problems cost nothing extra.
  • While typing on a line with an error, the old message stays until the server answers, so typing doesn't redraw it twice.
  • The line tint is one FillRect per row, already drawn for the current line today.

2. Rename the matching tag like Auto Rename Tag

With the caret in a tag's name, both the opening and closing names get a thin outline. Typing changes both, and one Ctrl+Z undoes both. Works in HTML, JSX/TSX and Vue/Svelte templates where the grammar is installed.

Typing section over div:
index.html
8<body>
9 <sect class="hero">
10 <h1>Welcome</h1>
11 <p>Fast, light, native.</p>
12 </sect>
13</body>
Both names change together
● 0Ln 9, Col 9HTML

Details

  • Setting linkedTagRename, on by default.
  • The pair comes from the Tree-sitter tree the syntax worker already keeps. No language server needed.
  • Typing a space or Esc ends the link. Self-closing tags and mismatched pairs are left alone.
  • The closing name is edited through replace_range inside one undo group, so LSP and syntax see both changes.

Speed

  • The pair is found once, when the caret enters a tag name, not on every key.
  • Each key makes one extra small edit, on a row that's usually already on screen.

3. File path suggestions like Path IntelliSense

Typing ./ or ../ inside a string opens the usual completion box with the files and folders there, using the Explorer's icons. Choosing a folder adds / and opens the next list.

app.js
1import { render } from "./ui/render.js";
2import { loadConfig } from "./src/con";
3
4const cfg = loadConfig();
JSconfig.jsfile
TSconstants.tsfile
▰controllersfolder
{}config.schema.jsonfile
src/ · 4 of 23

Details

  • Setting pathCompletion, on by default.
  • Paths are relative to the file's folder. Folders and files the Explorer hides (.gitignore, node_modules) are hidden here too.
  • Shown alongside language-server suggestions in the same box, with paths first inside a string.

Speed

  • One folder is read, on a worker, only after ./ or ../ is typed in a string. Nothing runs for other keys.
  • The listing is kept until the watcher reports a change in that folder, so typing more letters only filters it.
  • Large folders are capped (proposed: 500 entries) so a huge folder can't stall the box.

4. TODO highlighting like Todo Highlight / Todo Tree

TODO, FIXME, HACK and NOTE inside comments get their own colour, with a small mark on the scrollbar so you can find them in a long file. Find TODOs in Workspace in the Command Palette lists them all, using the Search in Files you already have.

Details

  • Setting todoHighlight, on by default. The words can be changed with todoKeywords (proposed).
  • Only inside comments, using the comment ranges the syntax worker already finds, so "TODO" in a string or a variable named todo isn't marked.
  • The workspace list runs the existing project search with a fixed pattern, so it obeys .gitignore and is cancelled when you close it. No index is kept.

Speed

  • Matched on comment spans while the syntax worker colours them, off the UI thread. Painting just uses one more colour.
  • Scrollbar marks reuse the existing scrollbar's marks for errors and search hits.

5. .editorconfig support like EditorConfig for VS Code

When a project has an .editorconfig file, the file follows it: indent size, spaces or tabs, line endings, a final newline and trimming trailing spaces on save. The status bar says where the setting came from, and clicking it shows which rules apply.

Details

  • Setting editorConfig, on by default. .editorconfig beats tabSize / insertSpaces; a language extension's tab_size comes after both.
  • Supported keys: indent_style, indent_size, tab_width, end_of_line, charset (utf-8 only), insert_final_newline, trim_trailing_whitespace, root.
  • Trimming and the final newline are applied at save time as one undoable edit, never while typing.

Speed

  • Read once when a file opens: walk up the folders to root = true, parse a few small files, cache them per folder.
  • The cache is dropped when the watcher reports that an .editorconfig changed. Nothing is read while typing.
  • Lives in the library crate (portable), next to gitignore.rs.

Suggested order

  1. Errors at the end of the line: the most visible, and the data already exists.
  2. .editorconfig: small, and fixes wrong indentation in many projects.
  3. TODO highlighting: small, reuses comments and project search.
  4. Rename the matching tag: needs care around undo and multi-cursor.
  5. File path suggestions: needs a new source in the completion box.
