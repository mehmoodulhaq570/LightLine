LightLine layout: current and proposed

Left is a real screenshot of LightLine today (current main, 1600 × 1000 at 125% scaling, rust-analyzer running, Problems panel open). Right is the proposed flatter, tighter layout at the same size with the same files, code and problems. Colors, fonts, icons and the menu bar stay the same; what changes is spacing and structure: thinner bars, panels that meet edge to edge with a 1 px line instead of floating cards, editor-coloured tabs and breadcrumbs, and denser lists. The code area gains two rows at this window size.

Swipe: drag across the picture to slide between current (left of the line) and proposed.

  • Sizes are in Windows' unscaled pixels; the pictures are at 125% (one unscaled pixel is 1.25 pixels there).
  • Unchanged: colours and themes, the code font and line height, icons, the menu bar, the search box, every shortcut.
  • Focus: the panel with the keyboard gets a thin accent line (as the active tab and Problems tab show), instead of a whole lighter card.
  • Speed: thinner chrome is less to paint; nothing here adds work while typing or scrolling.

Smoother motion

Short and only while something changes: nothing animates while idle (still 0 wakeups), typing is never animated, and all of it follows Windows' "Show animations" setting plus a LightLine setting to turn it off. Try each pair; left is how LightLine moves today.

Smooth scrolling

Page Down, a wheel notch or a jump glides over about 100 ms instead of moving at once (the existing smoothScrolling setting, which does nothing yet).

Today: instant
Proposed: glide
